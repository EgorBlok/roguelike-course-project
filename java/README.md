# Лабораторная работа №3 - часть 1 (Java)

Перенесены три класса из ЛР №2: `Hero`, `Enemy`, `Inventory`. Дополнительный класс `GameLog` демонстрирует `AutoCloseable`.

## Сборка и запуск из командной строки

Из корневой папки проекта:

**Windows PowerShell:**

```powershell
javac -encoding UTF-8 -d out java/src/*.java
java -cp out Main
```

## Что демонстрируется

1. Композиция: `Hero` сам создаёт `Inventory`, не выдаёт наружу ссылку на него. Методы `addItem`, `removeItem`, `equipTalisman` делегируют операции инвентарю.
2. Агрегация: `Enemy` создаётся вне `Hero`, передаётся в `setEnemy` и продолжает существовать отдельно от героя.
3. Проверка правила: шестой предмет отклоняется при лимите 5; отрицательное количество монет отклоняется.
4. Присваивание `Hero second = first` копирует ссылку, а не объект.
5. `try`-with-resources вызывает `GameLog.close()` при выходе из блока. Это закрытие ресурса, а не удаление объекта.
6. `WeakReference` и `System.gc()` показывают работу сборщика мусора. `System.gc()` — запрос, а не гарантия, поэтому вывод после вызова может отличаться.

## Отличия от C++ версии

- Не используются `delete`, деструкторы и указатели C++.
- Поля объектов в Java - ссылки, а не объекты по значению.
- Методы переименованы по соглашениям Java (`TakeDamage` - `takeDamage`, `GetHealth` - `getHealth`).
- Данные выводятся через переопределённый `toString()`.
- Время уничтожения недостижимых объектов определяется JVM, а не выходом из области видимости.
